### 2.2 新建文件位置规则

| 要新增的东西 | 放哪里 | 是否需额外注册 |
|------------|-------|--------------|
| 服务端接口 | 直接写在 `LightMDKit/server.js`（`main()` 调用之前） | 否 —— 无路由分层，全文件集中 |
| 服务端工具函数 | `LightMDKit/server.js` 中路由区之后、`main()` 之前（如 `sleep`/`isPortInUse`/`spawnDaemon` 的排布） | 否 |
| 前端新脚本文件 | `LightMDKit/public/` 下新建 `.js` | **是** —— 必须在 `index.html` 底部用 `<script src="x.js?v=1">` 引入，且**带 `?v=` 版本号** |
| 前端新逻辑（绝大多数情况） | 追加进 `LightMDKit/public/app.js` 的 IIFE 内 | 否 |
| Markdown 渲染规则改动 | `LightMDKit/public/md-render.js` | **是** —— 前后端共用，改完服务端 `require` 与浏览器 `<script>` 同时生效；**要同步升高 `index.html` 里的 `?v=`** |
| 新样式 | `LightMDKit/public/style.css` 追加 | **是** —— 要升高 `style.css?v=` |
| 打包/构建辅助脚本 | `LightMDKit/scripts/` | 是 —— 在 `package.json` 的 `scripts` 中挂载 |

**放 `public/` 下的文件无需写路由**：`LightMDKit/server.js:14` 用 `express.static(path.join(__dirname, 'public'))` 一次性托管整个目录。

### 2.3 本项目特有的硬约定：改前端资源必须升 `?v=`

`index.html:19`、`112`、`113` 三个本地资源都带查询串版本号：

```html
<link rel="stylesheet" href="style.css?v=46">
...
<script src="md-render.js?v=5"></script>
<script src="app.js?v=82"></script>
```

`index.html` 头部另有四行禁用缓存（`index.html:6-8`）：

```html
<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">
<meta http-equiv="Pragma" content="no-cache">
<meta http-equiv="Expires" content="0">
```

**规则**：`index.html` 本身不缓存，但它引用的 `style.css` / `app.js` / `md-render.js` 会被浏览器强缓存。**每次改动这三个文件之一，必须把对应的 `?v=N` 加 1**，否则用户刷新后仍是旧代码（此问题已收录在 [排障指南](./排障指南.md) 4.2 节）。

三方库（CodeMirror / Mermaid / marked / github-markdown-css）则**一律从本地 `public/vendor/` 加载，禁止引 CDN**：

```html
<link rel="stylesheet" href="vendor/github-markdown-css/github-markdown.min.css?v=1">
<link rel="stylesheet" href="vendor/codemirror/codemirror.min.css?v=1">
<script src="vendor/mermaid/mermaid.min.js?v=1"></script>
<script src="vendor/marked/marked.min.js?v=1"></script>
```

**为什么**：本工具会部署到**不能上网**的机器上。2026-10-08 的报障就是这条被违反的后果 —— 当时 10 个前端依赖全走 `cdn.jsdelivr.net`，离线时 `<script>` 全部加载失败，`window.marked` 变成 `undefined`，客户端重渲染抛 `Cannot read properties of undefined (reading 'parse')`（报障原文），而服务端预渲染的首屏反而正常，看起来像"打开文件才崩"。

`vendor/` 下的文件是上游 min 产物的**原样副本**（未做任何改动），按上游包内目录组织；行尾注释记着上游包与版本。升级某个库：取新版本覆盖同名文件，并把该行 `?v=` 的数字加一 —— 与上面 `style.css` / `app.js` 那套缓存戳是同一个约定。

改前端依赖后除了跑常规回归，还要跑一次断网验收：

```bash
node scripts/test-server.mjs                                       # 3459，磁盘版 public/
MARKDOWNLITE_URL=http://localhost:3459 node scripts/offline-check.mjs
```

## 3. 代码分层职责

本项目**没有传统的 Controller / Service / DAO 分层**。真实的分层是"进程边界"分层：服务端（Node）与前端（浏览器）各只有 1 个逻辑文件，靠 REST 与全局变量（`marked` / `CodeMirror` / `mermaid` / `MdRender`，均由 `index.html` 引入）衔接。

### 3.1 服务端路由层（Express）

- **职责**：HTTP 请求处理、参数校验、文件系统读写、Markdown 渲染、错误响应
- **特点**：4 个路由全部平铺在 `server.js` 中，**无 Router 拆分、无中间件封装**；每个处理函数内自校验、自处理异常
- **典型签名**：`app.method('/api/xxx', (req, res) => { ... })`，全部为同步逻辑（唯一异步点是子进程回调）
- **参考代码**：`LightMDKit/server.js:19-94`（/api/select-folder）、`LightMDKit/server.js:97-168`（/api/load）、`LightMDKit/server.js:171-196`（GET /api/file）、`LightMDKit/server.js:199-224`（/api/refresh）

### 3.2 服务端进程管理层（守护进程）

- **职责**：端口占用检测 → 拉起后台守护进程 → 打开浏览器 → 主进程退出
- **特点**：与路由层同文件但物理隔离，位于文件末尾（`LightMDKit/server.js:226-311`），只依赖环境变量 `LIGHTMDKIT_DAEMON` 区分"启动器"与"守护进程"两种身份
- **参考代码**：`LightMDKit/server.js:265-311`

### 3.3 渲染共享层（UMD）

- **职责**：Markdown 预处理（缩进保留、表格续行合并、单波浪线删除线修正）与渲染
- **特点**：**同一份文件同时被 Node 与浏览器加载**，用 UMD 包装（`md-render.js:1-7`），是唯一一处"前后端复用"的代码
- **典型签名**：`renderMarkdown(markdown, marked)` —— `marked` 由调用方注入，避免模块内 `require`
- **参考代码**：`LightMDKit/public/md-render.js:1-7`、`LightMDKit/public/md-render.js:190-197`
- **服务端用法**：`LightMDKit/server.js:7` `const { renderMarkdown } = require('./public/md-render.js');`
- **前端用法**：全局 `MdRender`（`index.html:112` 引入），`LightMDKit/public/app.js:1121`

### 3.4 前端交互层（单个 IIFE）

- **职责**：DOM 操作、事件响应、File System Access API 读写、目录/内容渲染、模式切换、拖放打开
- **特点**：**全部逻辑封装在一个 `(function () { ... })()` 内**，不暴露任何对外 API（`app.js:1` 开头 / `app.js:2132` 结尾），也不使用 `'use strict'`（见 5.7 的偏差说明）
- **参考代码**：`LightMDKit/public/app.js:1-2154`

### 3.5 样式层（纯 CSS）

- **职责**：布局、GitHub 观感、状态样式、现代模式的即时渲染效果
- **特点**：**无 CSS 预处理器、无 CSS 变量**（全文没有 `:root` / `var(--x)`），颜色一律写字面色值；与 HTML 结构同序
- **参考代码**：`LightMDKit/public/style.css:1-1002`

### 3.6 层间调用规则

```
server.js ──require──▶ md-render.js          （服务端渲染，供 REST 接口使用）
                              ▲
index.html ──<script>──▶ md-render.js ── 全局 MdRender ──▶ app.js
```

- **前端不调用 REST 接口**：文件读写走浏览器 File System Access API（`showDirectoryPicker`），`server.js` 的 4 个接口是"替代或扩展"通道（README 已声明）。改前端功能时**不要顺手去调 `/api/load`**。
- **渲染入口唯一**：任何地方渲染 Markdown 都必须走 `MdRender.renderMarkdown(text, marked)`（`app.js:1108`、`1671`、`1699`），不要直接调 `marked.parse`，否则表格续行、单波浪线等修正会失效。

## 5. JavaScript 编写规范

### 5.1 IIFE 结构模板

`app.js` 的内部组织顺序是稳定的六段式，新增代码请插入对应段落：

```javascript
(function () {
  // ① DOM 引用（const，集中声明）        app.js:2-28
  // ② 状态变量（let / const，带用途注释）  app.js:30-103
```

### 5.2 注释规范（本项目最重要的特征）⭐

### 5.3 状态管理

- **状态即模块级变量**，没有状态容器、没有发布订阅。任何函数都可以直接读写 `currentFile`、`currentMode` 等。
- **状态变更后必须显式调用"同步 UI"的函数**，而非依赖响应式。典型序列（`app.js:1146-1150`）：

```javascript
    applySurface();       // 决定浏览区/编辑器谁可见
    renderToc();          // 重建目录
    // 只更新高亮不重建列表：过滤框里正打字时重建会让输入框失焦
    updateActiveFileItem();
    renderMermaid();
```

- **`applySurface()` 是界面形态的唯一收口**（`app.js:1576-1626`）：传统-浏览 / 传统-编辑 / 现代 三种形态的显隐**只能**由它决定，禁止在业务函数里写 `xxx.style.display = ...`。原注释写得很明确：

```javascript
  // 三种界面形态（传统-浏览 / 传统-编辑 / 现代）的显隐统一由这里决定，
  // 不再散落在 toggleEditMode、loadFile、renderFile 各处分别写内联 style。
```

- **需要持久化的界面偏好**走 localStorage，键名以 `lightmdkit.` 为前缀，且**读取必须容错**（`app.js:47-54`）：

```javascript
  const MODE_STORAGE_KEY = 'lightmdkit.mode';
  let currentMode = loadModePreference();

  function loadModePreference() {
    try {
      return localStorage.getItem(MODE_STORAGE_KEY) === 'modern' ? 'modern' : 'traditional';
    } catch (e) {
      // 隐私模式/禁用存储时 localStorage 会抛异常，回退传统模式
      return 'traditional';
    }
  }
```

  写入同样要包 `try/catch`（`app.js:56-62`，注释：`// 存不下不影响本次使用`）。

- **高频重算结果要缓存**（`app.js:346-353`）：

```javascript
  // getValue() 是 O(n)，而光标移动很频繁，这里按文本内容缓存解析结果
  let headingCache = { text: null, list: [] };
  function getHeadingsCached(text) {

      headingCache = { text, list: extractHeadings(text) };

    return headingCache.list;

```

- **状态声明的位置**：优先在顶部 ② 段集中声明；**与之强耦合、仅服务单个功能的临时状态允许就近声明**，但必须带注释。现有就近声明有：`headingCache`（`:337`）、`livePreviewTimer`（`:398`）、`strikeMarks`（`:413`）、`isResizing`（`:1159`）、`dragDepth`（`:1335`）、`observer`（`:1421`）。

### 5.4 异步与错误处理

**统一的前端错误处理三段式**（`app.js:1271-1274`、`app.js:1338-1341`、`app.js:1547-1551`、`app.js:2078-2081` 等 8 处）：

```javascript
    try {
      ...
    } catch (e) {
      console.error(e);
      setStatus(e.message, 'error');
    }
```

规则：

1. **底层异常必须先 `console.error(e)` 留痕，再 `setStatus(e.message, 'error')` 提示用户**。两件事都要做，不许只留其一。
2. **用户可见文案是中文**，但错误详情直接用底层 `e.message`（可能英文），**不做翻译**：`setStatus('保存失败: ' + e.message, 'error')`（`app.js:1549`）。
3. **面向用户的校验失败不抛异常，直接 `setStatus(..., 'error')` 后 `return`**（`app.js:1686-1689`）：

```javascript
    if (!currentFile) {
      setStatus('请先加载文件', 'error');
      return;
    }
```

4. **只有"调用方需要据此改变流程"时才 `throw`**。全项目仅一例：`saveCurrentFile` 保存失败后 `throw e`（`app.js:1550`），以便 `startAutosave` 捕获后停掉定时器（`app.js:1556-1564`）。
5. **静默模式用 `silent` 参数**，而非另写一个函数（`app.js:1531` `async function saveCurrentFile(silent = false)`）：自动保存传 `true`，不弹提示。
6. **可忽略的失败要写注释说明为什么可以忽略**（`app.js:1100-1112`、`app.js:1918`、`app.js:1932`）：

```javascript
      } catch (e) {
        // 忽略错误，回退到传入的句柄
      }
```

```javascript
    } catch (e) { /* IndexedDB 不可用时忽略 */ }
```

7. **取消操作不算错误**：`selectFolder` 单独识别 `AbortError`（`app.js:1244-1250`）。

```javascript
    } catch (e) {
      if (e.name === 'AbortError') {
        setStatus('已取消');
      } else {
        console.error(e);
        setStatus(e.message, 'error');
      }

    }
```

**模式二：节流重算用定时器 + 模式守卫**（`app.js:407-418`）：

### 5.7 历史偏差（已修复）：`app.js` 的隐式全局

**该缺陷已修复，此处留档是为了说明「为什么 IIFE 里不能出现未声明的赋值」。**

`app.js:2130` 的 `renderToc = function () { ... }` 曾**没有 `let` / `const` / `function` 声明**，且 `app.js` 全文没有 `'use strict'`（对比 `md-render.js:8` 有）。当时：

- `renderToc` 实际是**挂在 `window` 上的全局变量**，与 5.1 节「IIFE 避免污染全局命名空间」的初衷相悖；
- 运行期能工作，仅因为所有调用点都在赋值语句之后才真正执行。**任何「在文件中部提前调用 `renderToc()`」的改动都会 `ReferenceError`**。

**修复方式**：已在 `app.js:44` 补上 `let renderToc;`（声明与赋值分离）；文末 `:1463-1468` 赋值时先用 `const renderTocContent = renderToc;` 留住被装饰目标，再重绑定为带视图守卫的版本。

**新增代码的正确做法**：若确需装饰，先声明再赋值。不要新增任何未声明的赋值 —— 本项目没有 `'use strict'` 兜底，这类错误不会被自动发现。

## 7. 服务端编写规范

### 7.1 路由写法模板

每个路由都是**平铺的 `(req, res) => {}`**，内部固定四步：**注释说明 → 取参 → 校验 → 处理/响应**。照抄 `app.js` 之外唯一的路由文件 `server.js`：

```javascript
// GET /api/file - read a specific file
app.get('/api/file', (req, res) => {
  const filePath = req.query.path;

  if (!filePath) {
    return res.status(400).json({ error: 'path query parameter is required' });
  }

  const resolvedPath = path.resolve(filePath);

  if (!fs.existsSync(resolvedPath)) {
    return res.status(404).json({ error: 'File does not exist: ' + resolvedPath });
  }

  const stats = fs.statSync(resolvedPath);
  if (!stats.isFile()) {
    return res.status(400).json({ error: 'Path is not a file: ' + resolvedPath });
  }

  try {
    const content = fs.readFileSync(resolvedPath, 'utf-8');
    const html = renderMarkdown(content, marked);
    res.json({ content, html, path: resolvedPath });
  } catch (err) {
    return res.status(500).json({ error: 'Failed to read file: ' + err.message });
  }
});
```
（出处：`LightMDKit/server.js:170-196`）

**要点**：

1. **路由前必须有 `// METHOD /path - 英文短说明` 单行注释**（`LightMDKit/server.js:18`、`96`、`170`、`198`）。全项目 4 个路由无一例外。
2. **入参一律 `path.resolve()` 后再校验**——`existsSync` → `statSync` → `isFile()/isDirectory()` 三连（`LightMDKit/server.js:104-113`、`178-187`、`206-215`）。
3. **提前返回用 `return res.status(...).json(...)` 一行写完**，不写 `else`。
4. **错误信息用英文短句 + `: ` + 具体值/`err.message`**（`LightMDKit/server.js:107`、`144`、`157`）。
5. **同步 FS API**（`existsSync`/`statSync`/`readFileSync`/`readdirSync`）是本项目的有意选择：单用户本地工具，无需为 I/O 做异步改造。**新增路由请沿用同步写法**。
6. **响应字段用 camelCase**（`folderPath`、`currentFile`、`filePath`）。
7. **只读接口用 `GET` + query（`?path=`），带副作用的用 `POST` + body**（`/api/refresh` 是 POST，因为语义上是"要求重扫"）。

### 7.2 错误处理规范

状态码使用是收敛的，只有 4 种：

| 状态码 | 触发条件 | 出处 |
|-------|---------|------|
| `400` | 必填参数缺失（`'folderPath is required'`）；传了文件但期望目录（或反之） | `LightMDKit/server.js:101`、`112`、`149`、`175`、`186`、`203`、`214` |
| `404` | 路径不存在 | `LightMDKit/server.js:107`、`144`、`181`、`209` |
| `500` | 系统能力/IO 失败（非 Windows 弹窗、PowerShell 失败、超时、目录不可读、文件不可读） | `LightMDKit/server.js:22`、`68`、`75`、`129`、`157`、`194`、`222` |
| `200`（默认） | 成功时**直接 `res.json(payload)`，不写 `res.status(200)`** | `LightMDKit/server.js:92`、`161`、`192`、`220` |

**唯一响应格式**：

```javascript
res.status(400).json({ error: 'folderPath is required' });   // 失败：只有 error 字段
res.json({ path: selectedPath });                            // 成功：业务字段
```

**取消语义不用错误码**：用户在弹窗里点"取消"时返回 `200` + `{ cancelled: true }`（`LightMDKit/server.js:79-81`），由前端判断，而不是 4xx。

**进程级错误**（无 HTTP 响应可写）走 `console.error` + `process.exit(1)`（`LightMDKit/server.js:280-288`）：

```javascript
  server.on('error', (err) => {
    if (err.code === 'EADDRINUSE') {
      console.error(`Port ${PORT} is already in use.`);
      process.exit(1);
    } else {
      console.error('Server error:', err.message);
      process.exit(1);
    }
  });
```

### 7.3 日志记录规范

**API**：只用 Node 内置 `console.*`，无日志库、无日志文件、无级别配置。

**实际用法分布（与"统一加 `[LightMDKit]` 前缀"的预期不符，如实记录）**：

| 场景 | 写法 | 出处 |
|-----|------|------|
| **接口被调用**（入口埋点） | `console.log('[LightMDKit] /api/select-folder requested')` | `LightMDKit/server.js:20` —— **全项目唯一带前缀的接口日志** |
| 服务启动成功 | `console.log(\`LightMDKit started at ${url}\`)` | `LightMDKit/server.js:301`（**无前缀**） |
| 端口占用提示 | `console.log('\n端口 3456 已被占用，LightMDKit 可能已在运行。')` | `LightMDKit/server.js:307-308`（**无前缀**，且是中文） |
| 子进程错误详情 | `console.error('PowerShell stderr:', stderr)` | `LightMDKit/server.js:74`（**无前缀**） |
| 服务/进程错误 | `console.error('Server error:', err.message)` | `LightMDKit/server.js:285`（**无前缀**） |
| 前端图片加载失败 | `console.warn('[LightMDKit] 图片加载失败:', rel, e)` | `app.js:1196` —— **前端唯一带前缀的日志** |
| 前端其他异常 | `console.error(e)`（裸错误对象） | `app.js:1248`、`1272`、`1293`、`1339`、`1548`、`2028`、`2042`、`2079` |
| 可降级的初始化失败 | `console.warn('CodeMirror/Mermaid init failed, falling back to textarea:', e)` | `app.js:156` |

**结论与新增代码建议**：

- 前缀 `[LightMDKit]` 目前**不是全局约定**，只在"接口入口日志"和"启动脚本"（`start.bat`/`start.sh`/`stop.bat` 的 echo）中稳定使用。**新增接口调用日志请沿用 `[LightMDKit] /api/xxx requested` 格式**；其余错误日志保持 `console.error('描述:', err.message)` 的"英文短语 + 冒号 + 细节"写法即可，不必强加前缀。
- **不要引入日志库**（如 `winston`/`pino`）—— 项目零额外依赖的取向很明确（`package.json` 只有 `express` + `marked` 两个运行时依赖）。

### 7.4 进程模型要点

- **端口硬编码** `const PORT = 3456;`（`LightMDKit/server.js:11`），**没有环境变量覆盖机制**。若要改端口，需同时改此处与 README、排障指南。
- **两种身份靠环境变量区分**（`LightMDKit/server.js:226-227`、`291-295`）：

```javascript
const DAEMON_ENV = 'LIGHTMDKIT_DAEMON';

async function main() {
  if (process.env[DAEMON_ENV] === '1') {
    runDaemon();
    return;
  }
  ...
```

- 主进程负责"检测端口 → 拉起守护进程（`spawnDaemon`）→ 等 2 秒 → 打开浏览器 → 退出"（`LightMDKit/server.js:297-311`）；守护进程只 `app.listen`，**不自动打开浏览器**（`LightMDKit/server.js:276-278` 有注释说明原因）。
- 平台分支集中在 `openBrowser`（`LightMDKit/server.js:233-233`）：`win32` / `darwin` / 其余 `xdg-open`。

## 10. 本地持久化与数据兼容

**本项目不使用数据库**，没有 `migrations/`、`sql/` 目录。与"数据升级"等价的概念是**浏览器端持久化数据的键名与结构兼容**，规范如下。

### 10.1 localStorage

| 键 | 取值 | 定义位置 | 读写函数 |
|---|------|---------|---------|
| `lightmdkit.mode` | `'modern'` / `'traditional'` | `LightMDKit/public/app.js:48` | `loadModePreference()` / `saveModePreference()`（`:41-56`） |
| `lightmdkit.sidebarView` | `'toc'` / `'files'` | `LightMDKit/public/app.js:69` | `loadSidebarView()` / `saveSidebarView()`（`:62-77`） |

**规范**：

1. 键名前缀固定 `lightmdkit.`，用 `.` 分隔（**不是** `:` 或 `-`）。
2. **读取必须做白名单校验 + 默认值回退**，不能直接信任存储值：

```javascript
  function loadSidebarView() {
    try {
      return localStorage.getItem(SIDEBAR_VIEW_KEY) === 'toc' ? 'toc' : 'files';
    } catch (e) {
      // 隐私模式/禁用存储时 localStorage 会抛异常，回退文件列表
      return 'files';
    }
  }
```

3. **读写都要 `try/catch`**，存储不可用时静默降级，不能影响功能（`app.js:56-62`）。
4. **键名提为 `const XXX_KEY`**，不在业务代码里散写字面量。

### 10.2 IndexedDB（拖放句柄跨标签页传递）

| 项 | 值 | 位置 |
|---|----|------|
| 数据库名 | `'lightmdkit'` | `LightMDKit/public/app.js:1885` |
| 对象存储 | `'drops'` | `LightMDKit/public/app.js:1886` |
| 版本 | `1` | `LightMDKit/public/app.js:1891` |
| 记录有效期 | 24 小时（`DROP_TTL_MS`） | `LightMDKit/public/app.js:1887` |

**升级/兼容规范**（若将来要改结构）：

1. 结构变更**必须升高 `indexedDB.open(DROP_DB_NAME, 1)` 的版本号**，并在 `onupgradeneeded` 中判断 `objectStoreNames.contains` 后再建（`app.js:1870-1874`）——现有代码已是这个防御写法，直接沿用：

```javascript
  function openDropDb() {
    return new Promise((resolve, reject) => {
      const req = indexedDB.open(DROP_DB_NAME, 1);
      req.onupgradeneeded = () => {
        if (!req.result.objectStoreNames.contains(DROP_STORE)) {
          req.result.createObjectStore(DROP_STORE);
        }
      };
      req.onsuccess = () => resolve(req.result);
      req.onerror = () => reject(req.error);
    });
  }
```

2. **记录需带时间戳并主动清理**：写入时 `record.ts = Date.now()`（`app.js:1953`），启动时调 `idbPurgeExpired()`（`app.js:1922`）用游标删除过期记录（`app.js:1900-1919`）。
3. **清理失败必须吞掉**（`app.js:1918` `catch (e) { /* IndexedDB 不可用时忽略 */ }`），不能阻塞启动。

## 11. 配置文件编写规范

> 本项目是**代码驱动型项目**：配置文件只有 `LightMDKit/package.json` 一个，不承载业务逻辑，因此**不单独输出《配置文件编写指南》**，在此作为一节说明即可。

### 11.1 配置文件位置

| 配置类型 | 位置 | 命名格式 |
|---------|------|---------|
| 依赖与脚本 | `LightMDKit/package.json` | npm 标准 |
| 依赖锁定 | `LightMDKit/package-lock.json` | npm 自动生成 |
| 忽略规则 | `LightMDKit/.gitignore` | 每行一条，目录以 `/` 结尾 |
| 打包清单 | `LightMDKit/package.json` 的 `pkg` 字段 | 内嵌在 package.json |

非配置但常被误认为配置的：`start.bat`/`start.sh`/`stop.bat`/`stop.sh` 是**可执行脚本**（会检查 Node 环境、自动 `npm install`），不是配置文件，改动它们不需要重启服务。

### 11.2 配置文件格式

- **文件格式**：JSON（`package.json`），**不支持注释**
- **缩进**：2 空格
- **命名风格**：npm 字段用 camelCase（`devDependencies`）；包名用 kebab-case（`lightmdkit`）；脚本名用 `动词:平台` 或 `动词`（`start`、`build:win`）
- **`package.json` 顶层字段顺序**：`name` → `version` → `description` → `main` → `bin` → `scripts` → `pkg` → `dependencies` → `devDependencies`（新字段追加到对应分组，不要打乱现有顺序）

### 11.3 配置模板（当前实际内容）

**分析来源**：`LightMDKit/package.json`（唯一的 JSON 配置文件）

### 11.5 新增/修改配置

**新增运行时依赖**（需谨慎，优先考虑能否用现有两个依赖实现）：

1. `npm install <package>`（自动改写 `package.json` + `package-lock.json`）
2. 在 `server.js` 顶部按现有顺序追加 `require()`（`LightMDKit/server.js:1-8`：内置模块在前，三方模块在后）
3. **若该依赖在前端也需要**，把它的 min 产物放进 `public/vendor/<库名>/`，在 `index.html` 用相对路径 `<script>`/`<link>` 引入并带 `?v=1`，**不要添加到 `dependencies`**，**更不要引 CDN** —— 前端没有打包步骤（`node_modules` 里的包没法直接被浏览器加载），而本工具会部署到不能上网的机器上（离线下 CDN 会全部加载失败，见 [排障指南](./排障指南.md) 3.13 节）。行尾注释记上游包与版本，然后跑一次断网验收：`node scripts/test-server.mjs` + `MARKDOWNLITE_URL=http://localhost:3459 node scripts/offline-check.mjs`
4. `npm start` 验证服务可启动

**修改 `pkg` 打包范围**：改了 `public/` 之外的静态资源目录时，必须同步更新 `package.json` 的 `pkg.assets`，否则打包后运行时缺文件。改完执行 `npm run build:win` 重新出包。

**修改注意事项**：

- `package-lock.json` **不要手工编辑**，只通过 `npm install` / `npm ci` 变更
- 端口 3456 若要改，需同步更新 README.md、排障指南与本文档（没有配置项可改，只能改代码）
- 改完 `package.json` 的 `scripts` 后无需重启服务，改 `dependencies` 必须重新 `npm install`

### 12.2 如何加一个事件

以键盘快捷键 `Ctrl+S` 保存为例。

**全局事件**加在文末"事件绑定 + 启动初始化"段（`app.js:2002-2131` 区域），与既有的 `document.addEventListener('dragenter'|'dragover'|'dragleave'|'drop')` 并列：

```javascript
  document.addEventListener('keydown', async (e) => {
    if (!(e.ctrlKey || e.metaKey) || e.key !== 's') return;
    e.preventDefault();
    if (!isEditMode) return;
    try {
      await saveCurrentFile();
    } catch (err) {
      // 保存失败已由 saveCurrentFile 内部提示
    }
  });
```

**规范要点**：

1. **先 `return` 掉不关心的分支**，不要写嵌套 `if`。
2. **必须 `e.preventDefault()` 的场景**：会触发浏览器默认行为（Ctrl+S 保存页面、拖放打开文件）。参考 `app.js:2009` 的注释 `// 必须阻止默认行为才允许 drop；仅针对文件拖拽，避免影响编辑器内的文本拖放`。
3. **全局监听要判断是否该抢事件**：例如 `fileFilter` 的 Esc 清空监听会 `e.stopPropagation()`（`app.js:1839-1845`），避免被上层监听再次处理。
4. **元素级事件优先用委托**（见 5.5），只在容器上绑一次。
5. **元素可能不存在时先判空**（`app.js:1827`）。

以在**文件列表项上加双击重命名**为例（元素级委托）：

```javascript
  fileListEl.addEventListener('dblclick', (e) => {
    const item = e.target.closest('.file-item');
    if (!item) return;
    startRename(item.dataset.path);
  });
```

以"是否显示空状态提示"或更实际的"编辑器字号缩放比"为例。

**第 1 步：声明** —— 加到 `app.js:30-103` 的状态段，**必须带用途注释**：

```javascript
  // 编辑器字号缩放比（1 = 默认），只影响现代模式
  let editorZoom = 1;
```

若状态是**持久化的界面偏好**，照 `sidebarView` 的写法三件套：常量键名 + load + save（`app.js:65-83`）：

```javascript
  const ZOOM_STORAGE_KEY = 'lightmdkit.editorZoom';
  let editorZoom = loadEditorZoom();

  function loadEditorZoom() {
    try {
      const raw = parseFloat(localStorage.getItem(ZOOM_STORAGE_KEY));
      return Number.isFinite(raw) && raw >= 0.5 && raw <= 3 ? raw : 1;
    } catch (e) {
      // 隐私模式/禁用存储时 localStorage 会抛异常，回退默认值
      return 1;
    }
  }

  function saveEditorZoom(zoom) {
    try {
      localStorage.setItem(ZOOM_STORAGE_KEY, String(zoom));
    } catch (e) {
      // 存不下不影响本次使用
    }
  }
```

**第 2 步：提供唯一的变更函数** —— 状态只在一处被写，UI 副作用集中在这里：

```javascript
  function setEditorZoom(zoom) {
    editorZoom = zoom;
    saveEditorZoom(zoom);
    applySurface();   // 界面显隐/样式统一收口（若有样式需刷新）
  }
```

**第 3 步：接入界面刷新收口** —— 若新状态影响面较大，扩展 `applySurface()`（`app.js:1614-1659`）而不是在业务函数里散写内联样式。它已有的职责就是"三种界面形态的唯一决定者"：

```javascript
    if (cmEditor) {
      const wrapper = cmEditor.getWrapperElement();
      wrapper.style.display = editorVisible ? '' : 'none';
      wrapper.classList.toggle('live-preview', isModern);
      ...
    }
```

**第 4 步：启动时恢复** —— 在文末启动段（`app.js:2115-2131`）应用一次，紧挨着 `applySurface()` 与 `setSidebarView(sidebarView)`：

```javascript

  applyZoom();        // ← 新增
```

**第 5 步：清理定时器/监听** —— 若状态持有定时器（照 `autosaveTimer`）或 `IntersectionObserver`（照 `observer`，`app.js:2088-2093`），必须在切换/停止时显式清理，防止泄漏。

### 12.4 如何加一个服务端 API

以"获取文件元信息"为例。

**第 1 步：在 `server.js` 加路由** —— 插入到 `/api/refresh`（`LightMDKit/server.js:199-224`）之后、`const url = ...`（`LightMDKit/server.js:226`）之前。**必须带 `// METHOD /path - 说明` 注释**，并沿用第四章的四步结构：

```javascript
// GET /api/file-info - get file metadata
app.get('/api/file-info', (req, res) => {
  const filePath = req.query.path;

  if (!filePath) {
    return res.status(400).json({ error: 'path query parameter is required' });
  }

  const resolvedPath = path.resolve(filePath);

  if (!fs.existsSync(resolvedPath)) {
    return res.status(404).json({ error: 'File does not exist: ' + resolvedPath });
  }

  const stats = fs.statSync(resolvedPath);
  if (!stats.isFile()) {
    return res.status(400).json({ error: 'Path is not a file: ' + resolvedPath });
  }

  try {
    res.json({
      path: resolvedPath,
      size: stats.size,
      mtime: stats.mtime
    });
  } catch (err) {
    return res.status(500).json({ error: 'Failed to read file info: ' + err.message });
  }
});
```

**第 2 步：加调用日志**（若这是新接口，照 `LightMDKit/server.js:20` 的格式）：


### 12.5 如何加样式

1. **先定位段落**：按 6.1 的 `style.css` 十段结构，找到与页面位置对应的段，**插进该段内部**，不要追加到文件末尾。

### 12.6 加功能时的自查顺序

