# 外部接入指南

> 本文档指导外部系统安全、高效地调用 LightMDKit 提供的功能。

> 📋 **HTTP 接口列表**: 请参考 [API索引](./技术知识库/API索引.md)

---

## 0. 适用范围与安全声明（请先阅读）

LightMDKit 是一个**免安装的本地单机 Markdown 工作台**，其服务端存在的目的是为自带前端提供静态资源与一组本地文件读写接口，**并非设计为可供第三方集成的服务**。

在把本项目当作"被集成的服务"使用前，必须先明确以下事实（均经源码与运行时实测核实）：

| 事项 | 现状 | 影响 |
|------|------|------|
| 监听地址 | `app.listen(PORT)` 未指定 host，实测监听 `::`（**所有网卡**） | 不是仅本机可达，**同局域网内其他主机可通过 `http://<本机IP>:3456` 访问** |
| 认证鉴权 | **完全没有** | 任何能连通该端口的一方即拥有接口全部能力 |
| 传输加密 | 无 HTTPS，纯 HTTP | 明文传输 |
| 路径限制 | **无**。`/api/file`、`/api/load`、`/api/refresh` 接受任意文件系统路径 | 可读取服务进程权限下**任意文件**，不限于 Markdown |
| CORS | 未配置 `Access-Control-Allow-Origin` | 浏览器跨源脚本**读不到**响应；但不可依赖此点作为防护 |

> ⚠️ **结论**：本项目**只应在本机个人环境使用**。若确需接入，请先按 [第 6 章](#6-安全接入建议) 完成网络隔离（绑定回环地址 + 防火墙），否则等同于在本机开放一个无口令的任意文件读取端口。

## 1. 接入前准备

### 1.1 获取凭证

**不涉及**。

本项目未实现 API Key、OAuth、JWT、签名校验或任何形式的凭证体系，接入时**无需申请也无需携带**任何凭证。相应地，服务端也不存在配额（QPS / 调用量）限制、计费与用量统计。

### 1.2 客户端环境

**无官方 SDK、无客户端库、无包管理器发布物**。

调用方使用任意通用 HTTP 客户端即可，无需安装额外依赖：

| 语言 | 调用方式 | 示例入口 |
|------|---------|---------|
| curl | 命令行 | `curl.exe -s "http://localhost:3456/api/file?path=..."` |
| JavaScript (Node) | `fetch` / `http` 模块 | `await fetch('http://localhost:3456/api/load', {...})` |
| JavaScript (浏览器) | `fetch`（同源） | 仅当调用方页面本身由本服务在 3456 端口提供时才同源 |
| Python | `requests` | `requests.post('http://localhost:3456/api/load', json={...})` |

### 1.3 启动服务

以下四种方式效果等价，均以 `LightMDKit/server.js` 为入口：

```bash
# 方式一：npm（守护进程模式，端口空闲时启动并自动打开浏览器）
npm start

# 方式二：直接运行
node server.js

# 方式三：启动脚本（会先检查 Node.js 与 node_modules，缺失时自动 npm install）
start.bat     # Windows
./start.sh    # Linux / macOS

# 方式四：免安装绿色版（Windows，双击或命令行均可）
dist/lightmdkit.exe
```

**停止服务**：

```bash
stop.bat      # Windows：taskkill /F /IM lightmdkit.exe 与 node.exe
./stop.sh     # Linux / macOS：pkill
```

**运行模式说明**（源码：`LightMDKit/server.js:291-311`）：

- 首次执行时，`main()` 检测到 3456 端口空闲，会以守护进程方式（`detached` + 环境变量 `LIGHTMDKIT_DAEMON=1`）拉起子进程，等待 2 秒后打开浏览器，随后父进程退出。
- 若端口已被占用，**不会**重启或弹窗选择，而是打印"端口 3456 已被占用"并直接打开浏览器指向已有服务，然后退出。
- 守护进程子进程（`LIGHTMDKIT_DAEMON=1`）只监听端口，不打开浏览器，避免重复开标签页。

**服务地址**：`http://localhost:3456`

### 1.4 静态资源

服务通过 `express.static`（源码：`LightMDKit/server.js:14`）公开 `LightMDKit/public/` 整个目录：

| 资源 | 路径 | 对应文件 |
|------|------|---------|
| 前端页面 | `GET /` | `LightMDKit/public/index.html` |
| 前端逻辑 | `GET /app.js` | `LightMDKit/public/app.js` |
| 渲染模块 | `GET /md-render.js` | `LightMDKit/public/md-render.js` |
| 样式 | `GET /style.css` | `LightMDKit/public/style.css` |

### 1.5 关于"前端如何对接"（重要澄清）

**本项目自带前端并未调用任何 `/api/*` 接口。**

实测与源码核实：`LightMDKit/public/app.js` 中 `fetch` 出现次数为 **0**，`/api/` 出现次数为 **0**；前端改用浏览器原生 **File System Access API**（`LightMDKit/public/app.js:1248` 的 `window.showDirectoryPicker`，`mode: 'readwrite'`）直接读写本地目录。

因此：

- **`/api/*` 是一组"备用通道"**，由服务端提供但当前 UI 不使用（`README.md` 的"服务端 API"一节亦如此说明）。
- 前端只在**同源**下加载 `index.html` / `app.js` / `md-render.js` 等静态资源，不发起 XHR/fetch 请求，自然也不携带任何认证头。
- 需要浏览器**同源**能力的只有 `md-render.js` 模块（见 2.4 节「可复用模块导出」）。
- 接入方若要走 HTTP 接口，属于**直接使用备用通道**，而非复用前端既有链路。

## 2. 调用方式与示例

### 2.1 HTTP/RESTful API

服务基于 Express 4，共 **4 个**业务接口 + 1 个静态目录服务。所有接口**均无认证**。

**通用约定**：

- 请求体：`POST` 接口使用 `application/json`（由 `express.json()` 解析，源码 `LightMDKit/server.js:13`）。
- 路径参数：接受绝对路径或相对路径，服务端统一经 `path.resolve()` 规范化；Windows 下正斜杠 `/` 与反斜杠 `\` 均可。
- 响应：成功为 JSON；失败为 `{"error": "..."}` + 相应 HTTP 状态码。
- 响应中所有路径字段返回的是**规范化后的绝对路径**（Windows 下为反斜杠形式）。

---

#### 2.1.1 `POST /api/select-folder`

弹出 Windows 系统文件夹选择对话框，返回用户选中的目录路径。（源码：`LightMDKit/server.js:19-94`）

**请求**：无请求体。服务端以 `powershell.exe -EncodedCommand` 方式调用 Windows Forms 的 `FolderBrowserDialog`（UTF-16LE + Base64 编码脚本）。

**响应**：

```json
// 用户选中目录
{ "path": "D:\\Work\\docs" }

// 用户点击取消
{ "cancelled": true }
```

**调用示例**：

```bash
curl.exe -s -X POST http://localhost:3456/api/select-folder
```

```javascript
const res = await fetch('http://localhost:3456/api/select-folder', { method: 'POST' });
const data = await res.json();
if (data.cancelled) {
  console.log('用户取消了选择');
} else {
  console.log('选中目录：', data.path);
}
```

**限制与注意事项**：

- **仅 Windows 可用**；非 Windows 平台返回 `500 {"error":"Folder dialog is only supported on Windows"}`。
- 该接口会**在服务进程所在桌面弹出 GUI 窗口**，是阻塞式交互（超时 30 秒）。**不适合无人值守/服务端自动化调用**。
- 选中路径需通过 `fs.existsSync` 与 `isDirectory` 校验，否则返回 `400 {"error":"Invalid or non-existent path selected"}`。

---

#### 2.1.2 `POST /api/load`

扫描指定目录下的 Markdown 文件，并可选加载其中一个文件的内容与渲染结果。（源码：`LightMDKit/server.js:97-168`）

**请求字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `folderPath` | string | 是 | 要扫描的目录路径；缺失返回 `400 {"error":"folderPath is required"}` |
| `filePath` | string | 否 | 要加载的具体文件。**不传时自动选取扫描结果中的第一个文件**（源码为 `files[0]`，即 `fs.readdirSync` 顺序，NTFS 上通常为字母序，**不应依赖**） |

**响应字段**：

```json
{
  "folderPath": "D:\\Work\\docs",
  "files": [
    { "name": "a.md", "fullPath": "D:\\Work\\docs\\a.md" },
    { "name": "b.markdown", "fullPath": "D:\\Work\\docs\\b.markdown" }
  ],
  "currentFile": "D:\\Work\\docs\\a.md",
  "content": "# Markdown 原始文本",
  "html": "<h1>Markdown 渲染后的 HTML</h1>"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `folderPath` | string | 规范化后的目录绝对路径 |
| `files` | array | 目录下 Markdown 文件列表，元素为 `{name, fullPath}` |
| `currentFile` | string \| null | 实际加载的文件绝对路径；无文件可加载时为 `null` |
| `content` | string | 文件原始 Markdown 文本（UTF-8）；无文件时为 `""` |
| `html` | string | 渲染后的 HTML；无文件时为 `""` |

**行为细节（据源码核实）**：

- 文件名过滤只认扩展名 `.md` 与 `.markdown`（大小写不敏感，源码 `LightMDKit/server.js:120-127`）。
- 扫描是**非递归**的，只列出 `folderPath` **顶层**的文件。README 中"递归进入子目录"的能力由前端 File System Access API 实现，**本接口不具备**。
- `filePath` **不校验是否位于 `folderPath` 之内**：传入目录外的路径同样会被读取（实测传入 `C:/Windows/System32/drivers/etc/hosts` 可成功读取，返回的 `currentFile` 即为该路径）。
- 目录为空或无 Markdown 文件时，仍然返回 `200`，此时 `files: []`、`currentFile: null`、`content` 与 `html` 为空字符串。

**调用示例**：

```bash
# 仅扫描目录（自动加载第一个 Markdown 文件）
curl.exe -s -X POST http://localhost:3456/api/load \
  -H "Content-Type: application/json" \
  -d "{\"folderPath\":\"D:/Work/docs\"}"

# 扫描目录并指定加载的文件
curl.exe -s -X POST http://localhost:3456/api/load \
  -H "Content-Type: application/json" \
  -d "{\"folderPath\":\"D:/Work/docs\",\"filePath\":\"D:/Work/docs/readme.md\"}"
```

```javascript
const res = await fetch('http://localhost:3456/api/load', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    folderPath: 'D:/Work/docs',
    filePath: 'D:/Work/docs/readme.md'
  })
});
const data = await res.json();
console.log(data.files.length, '个 Markdown 文件');
console.log(data.html);
```

```python
import requests
r = requests.post('http://localhost:3456/api/load',
                  json={'folderPath': 'D:/Work/docs'})
data = r.json()
print(data['currentFile'], len(data['files']))
```

#### 2.1.3 `GET /api/file`

读取单个文件，返回原始内容与渲染后的 HTML。（源码：`LightMDKit/server.js:171-196`）

**查询参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 文件路径；缺失返回 `400 {"error":"path query parameter is required"}` |

**响应**：

```json
{
  "content": "# Markdown 原始文本",
  "html": "<h1>Markdown 渲染后的 HTML</h1>",
  "path": "D:\\Work\\docs\\readme.md"
}
```

**行为细节（据源码核实）**：

- **不限制扩展名**：传入任意文件（如 `.txt`、`.ini`、`.log`、无扩展名文件）均可读取，内容会被当作 Markdown 渲染。这也是本项目"任意文件读取"风险的直接来源。
- **不限制目录**：接受任意绝对路径，未做任何沙箱约束。
- 文件不存在返回 `404`；路径是目录而非文件返回 `400`。

**调用示例**：

```bash
curl.exe -s "http://localhost:3456/api/file?path=D:/Work/docs/readme.md"
```

```javascript
const url = new URL('http://localhost:3456/api/file');
url.searchParams.set('path', 'D:/Work/docs/readme.md');
const data = await (await fetch(url)).json();
console.log(data.html);
```

```python
import requests
data = requests.get('http://localhost:3456/api/file',
                    params={'path': 'D:/Work/docs/readme.md'}).json()
print(data['html'])
```

#### 2.1.4 `POST /api/refresh`

重新读取并渲染指定文件，语义与 `/api/file` 完全一致，差别仅在于参数传递方式（请求体而非查询串）。用于文件在外部被修改后重新获取最新内容。（源码：`LightMDKit/server.js:199-224`）

**请求字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `filePath` | string | 是 | 要刷新的文件路径；缺失返回 `400 {"error":"filePath is required"}` |

**响应**：与 `/api/file` 相同（`content` / `html` / `path`）。

**调用示例**：

```bash
curl.exe -s -X POST http://localhost:3456/api/refresh \
  -H "Content-Type: application/json" \
  -d "{\"filePath\":\"D:/Work/docs/readme.md\"}"
```

```javascript
const data = await (await fetch('http://localhost:3456/api/refresh', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ filePath: 'D:/Work/docs/readme.md' })
})).json();
console.log(data.path, '已刷新');
```

> 📌 `/api/file` 与 `/api/refresh` 功能重复，均无缓存：每次调用都实时读盘并重新渲染，因此**不存在"内容过期"问题**，二选一使用即可。

### 2.2 gRPC 服务

**不涉及**。本项目无 `.proto` 文件、无 gRPC 依赖、无 gRPC 服务端，全部对外能力均为 HTTP/JSON。

### 2.3 SDK 调用

**不涉及**。本项目未发布任何语言的 SDK / 客户端库，也未发布到 npm 等包仓库。`package.json` 中 `"private"` 虽未显式声明，但 `name: "lightmdkit"`、`version: "1.0.0"` 仅为本地应用标识，`bin` 指向 `server.js`（可本地 `npx`/直接执行，非可被 `require` 的库入口）。

### 2.4 可复用模块导出：`public/md-render.js`

本项目**唯一**可被外部代码（Node 或浏览器）复用的入口是渲染模块 `LightMDKit/public/md-render.js`。服务端自身即依赖它完成渲染（源码 `LightMDKit/server.js:7` 的 `require('./public/md-render.js')`），可作为纯函数库独立使用。

**模块形态**：UMD 包装（源码 `LightMDKit/public/md-render.js:1-7`）——Node 环境下通过 `module.exports` 导出；浏览器环境下挂载为全局 `window.MdRender`（`LightMDKit/public/index.html:112` 即以 `<script src="md-render.js?v=5">` 引入，前端经 `MdRender.renderMarkdown(...)` 调用，见 `LightMDKit/public/app.js:1121`）。

**依赖注入说明**：本模块**不依赖也不引入 `marked`**，`marked` 实例必须由调用方传入。这是本项目在 Node 侧需 `require('marked')` 后再传入的原因。

#### 2.4.1 导出函数

| 函数名 | 功能说明 | 签名 | 代码位置 |
|--------|---------|------|---------|
| `renderMarkdown` | 渲染入口：串联下述全部预处理后调用 `marked.parse` | `renderMarkdown(markdown: string, marked: object): string` | `LightMDKit/public/md-render.js:190` |
| `preserveIndent` | 保留行首缩进：把非结构性文本行的前导空白转为 `&nbsp;`（跳过围栏代码块） | `preserveIndent(markdown: string): string` | `LightMDKit/public/md-render.js:10` |
| `mergeTableCells` | 合并 GFM 表格的跨行单元格，用 `<br>` 连接续行 | `mergeTableCells(markdown: string): string` | `LightMDKit/public/md-render.js:96` |
| `patchStrikethrough` | 修补 `marked` 的删除线分词器，只认双波浪线 `~~` | `patchStrikethrough(marked: object): object` | `LightMDKit/public/md-render.js:167` |

**返回值与副作用**：

- 三个预处理函数与 `renderMarkdown` 均为**纯字符串变换**，返回新字符串，不修改入参。
- `patchStrikethrough` 有**副作用**：它会调用 `marked.use()` **就地修改传入的 `marked` 实例**。内部用 `WeakSet` 记录已打补丁的实例（源码 `LightMDKit/public/md-render.js:165`），因此对同一实例重复调用是**幂等**的，不会重复注册分词器。
- `renderMarkdown` 的调用顺序为：`patchStrikethrough(marked)` → `preserveIndent(...)` → `mergeTableCells(...)` → `marked.parse(..., { gfm: true, breaks: true })`。注意 `breaks: true` 意味着**单个换行即渲染为 `<br>`**，与 GitHub 默认行为（需行尾两空格）不同；`gfm: true` 开启 GFM 扩展。
- 传 `null`/`undefined` 或不含 `use` 方法的 `marked` 时，`patchStrikethrough` 直接原样返回，不会抛错。

**各预处理函数的行为细节**：

- `preserveIndent`：逐行处理，`^ {0,3}(```|~~~)` 视为围栏代码块起止，块内不做转换；块外仅当行首有空白且剩余内容**不是**列表项（`- + *` / `1.`）、引用（`>`）、表格（`|`）、标题（`#`）、围栏、分隔线时才转换。空格转 `&nbsp;`，制表符转 4 个 `&nbsp;`。
- `mergeTableCells`：仅在遇到分隔行（形如 `| --- | --- |`，正则 `^:?-{3,}:?$`）后才进入合并模式；带 `<br>` 拼接续行；遇到空行或新的 `|` 起始行则结束当前行合并。

**使用示例（Node）**：

```javascript
// 注意：marked 需由调用方提供，本模块不内置
const { marked } = require('marked');
const { renderMarkdown, preserveIndent, mergeTableCells, patchStrikethrough } =
  require('./public/md-render.js');

const html = renderMarkdown('# 标题\n\n范围 1~100 与 ~~删除~~', marked);
// => '<h1>标题</h1>\n<p>范围 1~100 与 <del>删除</del></p>\n'

// 也可单独使用某个预处理步骤
const indented = preserveIndent('    缩进文本');
// => '&nbsp;&nbsp;&nbsp;&nbsp;缩进文本'
```

**使用示例（浏览器，作为库引入）**：

```html
<!-- marked 是必需参数：MdRender 自己不带解析器，由调用方把 marked 传进来。
     服务已把 marked 放在 public/vendor/marked/marked.min.js 随包发布，
     直接引本地这一份即可，不要引 CDN（本工具部署环境可能不能上网）。 -->
<script src="http://localhost:3456/vendor/marked/marked.min.js"></script>
<script src="http://localhost:3456/md-render.js"></script>
<script>
  // 浏览器下模块挂载为全局 MdRender
  const html = MdRender.renderMarkdown('# 标题\n\n~~删除~~', marked);
  document.getElementById('out').innerHTML = html;
</script>
```

> ⚠️ **安全提醒**：`renderMarkdown` 的返回值**未经 HTML 消毒**，Markdown 中的原始 HTML（含 `<script>`、`onerror` 等）会原样透出。实测 `renderMarkdown('<img src=x onerror=alert(1)>', marked)` 返回的 HTML 中该标签完整保留。因此**只应对可信来源的 Markdown 使用**；若渲染不可信内容，请先接入 DOMPurify 等消毒库，切勿直接 `innerHTML` 注入。

#### 2.4.2 导出类型/类

**不涉及**。本模块为纯函数集合，不导出类、构造函数或配置对象。

## 3. 认证与授权

### 3.1 认证机制

**不涉及**。本项目**未实现任何认证机制**：

- 无 JWT / Token、无 API Key、无 OAuth、无 Basic Auth、无 Cookie/Session。
- 请求**不需要也不应**携带 `Authorization` 头；携带了也会被忽略（无中间件读取它）。
- `express.json()` 与 `express.static()` 之外**没有任何认证中间件**（源码 `LightMDKit/server.js:13-14` 即为全部全局中间件）。

### 3.2 授权机制

**不涉及**。无 RBAC、无角色/权限模型、无接口级权限校验。

唯一的"访问控制"是操作系统层面的文件权限——即以**运行服务进程的操作系统用户**的身份读写文件。换言之，接口的文件访问能力 = 该用户对文件系统的权限，服务本身不再施加任何额外约束。

### 3.3 网络暴露面（实测结果）

源码 `LightMDKit/server.js:276` 为 `app.listen(PORT, () => {...})`，**未传 host 参数**。按 Node.js 语义，省略 host 时监听未指定的 IPv6 地址 `::`（IPv6 不可用时为 `0.0.0.0`）——即通配地址 `0.0.0.0` / `::`，两种写法含义相同，都表示**所有网络接口**，而非回环。

实测本机运行状态下：

```
LocalAddress  LocalPort  OwningProcess
::            3456       32368
```

`LocalAddress` 为 `::` 而非 `127.0.0.1`，**证实服务并非仅监听回环地址**。这直接推翻了"本地工具天然不可被外部访问"的常见假设——同一局域网内的其他主机可通过 `http://<本机IP>:3456` 直接访问上述全部接口（是否真正可达取决于本机防火墙是否放行该端口的入站连接）。

### 3.4 跨源访问（CORS）

**未配置任何 CORS 中间件**。实测对 `OPTIONS /api/load` 携带 `Origin: http://evil.example` 的预检请求，响应为：

```
HTTP/1.1 200 OK
Allow: POST
```

即由 Express 默认的 OPTIONS 处理器应答，**响应中不含任何 `Access-Control-Allow-Origin` / `Access-Control-Allow-Methods` 头**。因此：

- 浏览器中来自其他源的脚本**无法读取**本服务接口的响应内容（响应会被浏览器同源策略拦截）。
- 但**不能**把这个当作安全措施：该限制只约束"浏览器脚本读取"，对本机其他进程、命令行工具（curl）、以及局域网内的原生客户端**完全不生效**。且 `GET /api/file` 属简单请求，跨源页面仍可发起（只是读不到响应）。

## 4. 错误处理

### 4.1 错误响应结构

服务端**没有统一的业务错误码体系**，失败响应统一为单字段对象：

```json
{
  "error": "错误描述文本"
}
```

特点说明（据源码核实）：

- **无 `code` 字段**：判断错误类型只能依据 HTTP 状态码与 `error` 文案。
- **错误信息包含绝对路径**：如 `"File does not exist: C:\\nope\\nope.txt"`，会向调用方泄漏服务端文件系统路径信息。建议调用方在对外转发前自行脱敏。
- **无错误处理中间件**：源码中未注册 `app.use((err, req, res, next) => {...})` 兜底处理器。

### 4.2 常见错误码

| HTTP 状态码 | 触发场景 | 实际 `error` 文案示例 | 处理建议 |
|-------------|---------|----------------------|---------|
| 400 | 缺少必填参数 | `"folderPath is required"` / `"filePath is required"` / `"path query parameter is required"` | 检查请求体或查询串是否含必填字段 |
| 400 | 路径不是目录 | `"Path is not a directory: D:\\x.txt"` | 确认传递的是目录而非文件 |
| 400 | 路径不是文件 | `"Path is not a file: D:\\x"` | 确认传递的是文件而非目录 |
| 400 | 对话框所选路径无效 | `"Invalid or non-existent path selected"` | 仅 `/api/select-folder` |
| 400 | 请求体 JSON 格式错误 | **非 JSON**：Express body-parser 默认 HTML 错误页 | 校验 `Content-Type: application/json` 与 JSON 合法性 |
| 404 | 目录不存在 | `"Directory does not exist: D:\\nope"` | 检查路径拼写与盘符 |
| 404 | 文件不存在 | `"File does not exist: D:\\nope.md"` | 检查路径拼写 |
| 404 | 访问未定义路由 | **非 JSON**：Express 默认 HTML 404 页 | 核对接口路径拼写（无 `/v1` 前缀） |
| 500 | 读取目录失败 | `"Failed to read directory: ..."` | 检查目录权限 |
| 500 | 读取文件失败 | `"Failed to read file: ..."` | 检查文件权限或编码 |
| 500 | 对话框超时 | `"Folder dialog timed out"` | 30 秒内未完成选择，重试 |
| 500 | 非 Windows 平台调用对话框 | `"Folder dialog is only supported on Windows"` | 该接口仅 Windows 可用 |

### 4.3 非 JSON 错误的处理建议

以下两类错误**不会**返回 `{"error": ...}`，而是 Express 默认的 **HTML 错误页**，直接 `res.json()` 会抛解析异常：

1. **路由不存在**（404）——如误写成 `/api/loads`。
2. **请求体 JSON 非法**（400）——body-parser 抛出 `entity.parse.failed`。

建议调用方统一按如下方式处理：

```javascript
const res = await fetch('http://localhost:3456/api/load', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ folderPath })
});

const text = await res.text();
let data;
try {
  data = JSON.parse(text);
} catch {
  // 命中 Express 默认 HTML 错误页：多为路由拼错或 JSON 非法
  throw new Error(`非 JSON 响应 (HTTP ${res.status}): ${text.slice(0, 200)}`);
}

if (!res.ok) {
  throw new Error(`接口失败 (HTTP ${res.status}): ${data.error}`);
}
console.log(data.html);
```

**重试策略**：4xx 均为请求方问题，重试无意义；5xx 中读取类失败多为文件被占用或权限问题，可短暂延迟后重试一次。本服务单线程处理、无并发限制，**无需**做限流退避。

### 4.4 端口占用

端口 3456 被占用时，**不会**终止旧进程，也不会交互式询问；行为固定为三步——打印两行提示 → 打开浏览器 → `process.exit(0)`（源码 `LightMDKit/server.js:307-310`）：

```
端口 3456 已被占用，LightMDKit 可能已在运行。
打开访问地址: http://localhost:3456
```

> 📌 **澄清**：本仓库**不存在**按端口查找进程并结束的逻辑。`LightMDKit/server.js` 中全部 `spawn` 调用只有三处——`LightMDKit/server.js:45` 拉起 PowerShell 文件夹对话框、`LightMDKit/server.js:246` 打开浏览器、`LightMDKit/server.js:266` 拉起守护进程子进程；**没有** `taskkill`、`process.kill` 或任何进程查找/终止代码。旧版文档曾描述"提示用户选择『重新运行』或『显示访问 URL』"，属虚构或已失效的遗留内容，请以本节为准。

若需强制重启，请使用 `stop.bat` / `stop.sh`。

## 5. 版本管理与兼容性

### 5.1 API 版本化策略

**不涉及**。本项目**未采用任何版本化策略**：

- URL 路径**无版本前缀**（不是 `/v1/load`，而是 `/api/load`）。
- 无版本请求头（不接受 `Accept-Version`、`X-API-Version` 等）。
- 无版本常量定义，无 `api_version` 响应字段。

应用自身版本见 `LightMDKit/package.json` 的 `version` 字段，当前为 `1.0.0`，但**该版本号与 HTTP 接口契约无关**，接口未随应用版本演进做任何标记。

### 5.2 向后兼容性

由于服务端与前端同源同版本发布、且接口当前无外部已知调用方，项目**没有正式发布兼容性承诺**。实际情况如下：

| 变更类型 | 兼容性 | 说明 |
|---------|-------|------|
| 新增接口 | 兼容 | 新增路由不影响既有调用 |
| 新增可选请求字段 | 兼容 | 如给 `/api/load` 增加过滤选项 |
| 新增响应字段 | 兼容 | 调用方应**忽略未知字段**，不要严格校验 |
| 重命名/删除响应字段 | **不兼容** | 会直接破坏调用方 |
| 删除接口 / 改变必填字段 | **不兼容** | — |

**给接入方的建议**：

- 响应解析务必**容忍未知字段**（不要用严格 schema 校验），以便项目后续新增字段时不致失败。
- 对外部调用方而言，本项目的接口属于**无版本、无稳定性承诺**的内部接口；若需长期依赖，建议自行在中间层封装适配（如反向代理 + 自有接口层），而非直接耦合。
- 唯一的稳定点是对外契约极简（4 个接口、字段少），且项目已具备完整功能、改动频率低。

## 6. 安全接入建议

> 若只是本机个人使用，按默认方式启动即可。**若确需将本项目作为服务对外提供**，请务必完成以下加固，否则等同于在本机开放一个无口令的任意文件读取端口。

### 6.1 必做：限制网络可达性

**问题**：服务实测监听 `::`（所有网卡），局域网内其他主机可直接访问。

**加固方案（二选一）**：

1. **改绑定回环地址**（需修改源码，推荐）：

   ```javascript
   // LightMDKit/server.js:276 附近
   // 原：const server = app.listen(PORT, () => {
   // 改：
   const server = app.listen(PORT, '127.0.0.1', () => {
   ```

2. **用系统防火墙阻止外部访问 3456 端口**（不改代码）：

   ```powershell
   # Windows：仅允许本机访问（需管理员权限）
   New-NetFirewallRule -DisplayName "LightMDKit block inbound" `
     -Direction Inbound -Protocol TCP -LocalPort 3456 -Action Block
   ```

**验证方法**：加固后再次确认监听地址为 `127.0.0.1`：

```powershell
Get-NetTCPConnection -LocalPort 3456 -State Listen | Select-Object LocalAddress
```

### 6.2 高风险：任意文件读取

**问题**：`/api/file`、`/api/load`、`/api/refresh` 对路径**不做任何限制**——不限于 Markdown 扩展名、不限于任何根目录、不做沙箱约束。

**实测证据**（服务运行中）：

```bash
curl.exe -s "http://localhost:3456/api/file?path=C:/Windows/System32/drivers/etc/hosts"
# 成功返回该文件完整内容

curl.exe -s -X POST http://localhost:3456/api/load \
  -H "Content-Type: application/json" \
  -d "{\"folderPath\":\"D:/Work/docs\",\"filePath\":\"C:/Windows/System32/drivers/etc/hosts\"}"
# currentFile 返回 C:\Windows\System32\drivers\etc\hosts，即 filePath 可逃逸出 folderPath
```

**这意味着**：任何能访问 3456 端口的一方，可读取**服务进程所属用户权限范围内的任意文件**（如 SSH 私钥、`.env`、浏览器配置、其他项目源码等），配合 `/api/load` 的目录扫描能力还可枚举目录内容。

**加固方向**（需自行改造，本项目未实现）：

- 用 `path.resolve()` 后的结果与白名单根目录做前缀校验（注意 Windows 大小写与 `..`、符号链接/联结点的绕过）。
- 增加扩展名白名单，仅放行 `.md` / `.markdown`。
- 校验 `filePath` 必须位于 `folderPath` 之下（当前完全缺失该校验）。

### 6.3 中风险：渲染结果未消毒

**问题**：接口返回的 `html` 字段是 `marked` 的原始输出，**不转义原始 HTML**。

**实测证据**：

```javascript
renderMarkdown('<img src=x onerror=alert(1)>', marked)
// 返回：<img src=x onerror=alert(1)>   ← 原样保留
```

**风险**：调用方若把 `html` 直接 `innerHTML` 注入页面，且 Markdown 内容来自不可信来源，将导致 XSS。

**加固方向**：调用侧接入 [DOMPurify](https://github.com/cure53/DOMPurify) 等消毒库后再插入 DOM；本项目自带前端因只处理用户自己选择的本地文件，未做消毒。

### 6.4 其他注意事项

- **无 HTTPS**：HTTP 明文传输，敏感文件内容会以明文经过网络（这也是必须限制为回环访问的原因之一）。
- **信息泄漏**：错误信息与 `currentFile`/`path` 字段均返回服务端绝对路径；对外转发前应脱敏。
- **`/api/select-folder` 会弹出 GUI 对话框**：在共享桌面或非交互会话（如计划任务、SSH 会话）中调用会长时间阻塞至 30 秒超时，请勿在自动化流程中使用。
- **进程权限即服务权限**：服务以启动它的用户身份运行，不要以管理员/root 身份长时间运行本服务。
- **依赖供应链**：仅依赖 `express` 与 `marked`（均随包发布），依赖面很小。前端三方库（CodeMirror / Mermaid / marked / github-markdown-css）**已全部本地化**在 `public/vendor/`，不再依赖 `cdn.jsdelivr.net`，离线环境下页面功能完整（2026-10-08 起；此前走 CDN，离线时前端渲染会崩）。
