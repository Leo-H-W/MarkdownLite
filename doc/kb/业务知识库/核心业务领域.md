## 服务定位

### 业务场景

**LightMDKit** 是一款免安装的本地 Markdown 工作台：用户在本地启动服务后，用 Chrome / Edge 打开页面，直接选择一个本地文件夹，即可在其中**阅读、编辑、在文档间跳转**，全程文件不上传、不复制，改动直接写回磁盘上的原文件。

**典型场景**:
1. **项目文档速览**: 开发者把项目 `doc/` 或仓库根目录加载进来，侧边栏文件列表按目录分组列出全部 Markdown（含子目录），点击即读，不必逐个用编辑器打开。
2. **知识库维护**: 技术写作者一边读一边改，传统模式下点「编辑」改完点「浏览」即保存；或切到现代模式，像 Typora 一样边写边看，每 3 秒自动落盘。
3. **长文与图示阅读**: 阅读带层级标题的长文档，靠侧边栏目录（TOC）跳转、滚动高亮定位；含 Mermaid 图表、表格、本地截图的文档按 GitHub 风格渲染。
4. **多文档交叉核对**: 文档间用 `[xx](./yy.md)` 互相引用，点击链接在当前页面直接打开目标文件，「返回」按钮退回上一个文件。
5. **随手打开单个文件**: 从资源管理器把 `.md` 文件或整个文件夹拖进页面，在新标签页打开，不打断当前正在看的文件。

### 解决的问题

- 不用安装 VS Code / Typora 等重型编辑器，也不用把文档传到任何网站，就能获得结构化的 Markdown 阅读体验（目录导航、文件间跳转、滚动高亮）。
- 免去「打开编辑器 → 找文件 → 改 → 另存」的来回切换，把阅读与轻量修改放在同一个界面里完成。
- 免去把本地文档上传到在线 Markdown 预览站的隐私与操作成本 —— 文件始终留在本地磁盘。

### 业务价值

零安装、零上传、零账号即可获得接近 GitHub 的 Markdown 阅读与编辑体验，把「看文档」和「小改文档」的门槛降到打开一个浏览器标签页。

## 核心业务概念

### 业务实体（用户视角）

| 实体名称 | 对用户的含义 | 用户关心的属性 | 示例 |
|---------|-------------|--------------|------|
| 文件夹（文档库） | 用户一次性加载的本地目录，是文件列表与相对路径解析的基准 | 目录名、其中（含子目录）可打开的 Markdown 文件数量 | `D:\Work\leo-docs-store-svn\test\md-view\doc\kb` |
| Markdown 文件 | 用户阅读和编辑的文档单元 | 文件名、相对当前文件夹的路径、正文内容、是否已被外部改动 | `业务知识库/核心业务领域.md` |
| 文件列表 | 侧边栏中按目录分组展示的、当前文件夹下所有可打开文件 | 相对路径、所在目录分组、过滤关键字、当前高亮项、文件总数 | 「业务知识库」分组下的 `业务流程详解.md` |
| 目录（TOC） | 由当前文档标题自动生成的章节导航 | 标题层级（h1~h6）、标题文本、当前滚动 / 光标所在章节 | 「业务能力清单」 |
| 界面模式 | 用户选择的界面形态，决定是「编辑 / 浏览分离」还是「常驻即时渲染」 | 传统模式 / 现代模式（记忆在浏览器本地） | 现代模式 |
| 侧边栏视图 | 侧边栏当前展示的面板，与界面模式相互独立 | 文件列表 / 目录（TOC），记忆在浏览器本地 | 文件列表 |
| 阅读位置 | 在编辑 / 浏览之间切换时被记住的定位信息，用于切回后不丢失上下文 | 切换前视口最上方的标题、光标所在标题 | 切到编辑模式后光标停在「业务规则」 |
| 浏览历史（返回栈） | 由文件列表点击与文档内链接跳转形成的访问记录，供「返回」使用 | 访问过的文件相对路径（后进先出） | `README.md` → `docs/api.md` |

### 业务术语（用户视角）

- **加载文件夹 / 更换文件夹**: 位于**顶栏左侧**、紧跟目录名显示的按钮。首次点击选择目录，之后按钮变为「更换文件夹...」；既没有加载目录、也没有打开文件时点击「刷新」会提示先加载文件夹（`LightMDKit/public/app.js:997-1003`、`1043-1110`）。
- **传统模式**: 编辑与浏览分离的界面 —— 顶部有「编辑 / 浏览」按钮，只有进入编辑态后才能改动内容（`LightMDKit/public/app.js:1614-1657`）。
- **现代模式**: 只有一个常驻编辑区、由「现代模式 / 传统模式」按钮切换的界面；语法标记默认隐藏、光标所在行还原源码，效果对齐 Typora（`LightMDKit/public/app.js:1660-1703`）。
- **编辑态**: 内容以 Markdown 原文形式出现在编辑器里的状态；传统模式下点击「编辑」进入、点击「浏览」退出并保存，现代模式下则始终处于编辑态。
- **自动保存**: 编辑态下每 3 秒把编辑器内容写回原文件一次（`LightMDKit/public/app.js:98-99`、`1554-1572`）。
- **目录（TOC）视图**: 侧边栏的第二个面板，展示当前文档的标题结构，点击即跳到对应章节（`LightMDKit/public/app.js:1797-1816`）。
- **文件内链接跳转**: 文档中指向**相对路径** Markdown 文件的链接（如 `[详解](./业务流程详解.md)`）被拦截，改为在当前页面内打开目标文件；`http(s)`、`mailto`、`#锚点` 等链接不受影响（`LightMDKit/public/app.js:1505-1540`）。
- **返回**: 按历史栈退回上一个通过文件列表或链接打开的文件（`LightMDKit/public/app.js:1542-1551`）。
- **刷新**: 重新扫描当前文件夹（含子目录），感知新增 / 删除的文件，并重新读取当前文件内容（`LightMDKit/public/app.js:1293-1354`）。
- **拖放打开**: 把 `.md` / `.markdown` 文件或文件夹从资源管理器拖入页面，在新标签页打开；文件句柄经浏览器 IndexedDB 传递（`LightMDKit/public/app.js:1880-2022`、`2034-2082`）。
- **过滤框**: 文件列表上方的输入框，按文件名或相对路径实时筛选（大小写不敏感），按 `Esc` 一键清空（`LightMDKit/public/app.js:1038-1044`、`1813-1823`）。

## 业务能力清单

### 核心业务能力

#### 1. 加载本地文档库（打开文件夹）

**用户可以做什么**:
- 点击顶栏左侧「📁 加载文件夹...」选择本地目录，之后按钮变为「📁 更换文件夹...」以便换一个目录
- 一次性获得该目录**（含各级子目录）**中所有 `.md` / `.markdown` 文件的清单，顶栏左侧同时显示当前目录名
- 加载后自动打开第一个文件，不需要再指定

**使用场景**:
用户要通读一个项目文档目录或知识库，希望一次导入全部文档并在其中自由切换。

**操作示例**:
```
用户目标: 加载 D:\Work\...\doc\kb 目录下的全部知识库文档
操作步骤:
1. 启动 LightMDKit（npm start 或双击 exe），浏览器打开 http://localhost:3456
2. 点击顶栏左侧「📁 加载文件夹...」
3. 在系统文件夹选择对话框中选择目标目录
结果: 侧边栏文件列表按目录分组列出所有 Markdown（子目录也包含在内），
      顶部显示目录名，第一个文件自动打开并渲染
异常: 浏览器不支持该能力时提示「浏览器不支持文件夹选择，请使用 Chrome 或 Edge」；
      用户取消则提示「已取消」；目录里没有 Markdown 文件则显示「该目录下没有找到 Markdown 文件」
```

**源码位置**: `LightMDKit/public/app.js:1247-1266`（选择目录）、`1203-1231`（加载并扫描）、`230-254`（递归扫描）

#### 2. 浏览与查找文档

**用户可以做什么**:
- 在侧边栏文件列表中点击任意文件直接打开，当前文件高亮显示
- 用过滤框按文件名或路径实时筛选；按 `Esc` 清空过滤条件
- 在同一面板内切换「文件列表 / 目录」两种视图

**使用场景**:
文档数量多、层级深时，用户需要快速定位到某个文件，或按目录确认「这个文件在哪个子目录」。

**操作示例**:
```
用户目标: 打开知识库里的「业务流程详解.md」
操作步骤:
1. 侧边栏视图切到「文件列表」（面板顶部两个按钮：文件列表 / 目录）
2. 在过滤框输入「流程」
结果: 列表实时收敛到匹配项，按目录分组显示（如「业务知识库」分组下），
      点击即打开该文件；文件中已在列表里的同名项会高亮
```

**源码位置**: `LightMDKit/public/app.js:1023-1091`（列表渲染与分组）、`1034-1040`（过滤）、`1798-1802`（当前文件高亮）、`1775-1794`（视图切换）、`1813-1823`（过滤框与 Esc）

#### 3. 阅读 Markdown 文档（GitHub 风格渲染）

**用户可以做什么**:
- 以 GitHub 风格阅读渲染后的文档：标题、列表、表格、引用、代码块、行内样式
- 查看 ` ```mermaid ` 代码块渲染出的流程图 / 时序图
- 查看文档中通过**相对路径**引用的本地图片（含子目录）
- 通过目录（TOC）跳转章节，滚动阅读时目录自动高亮当前章节

**使用场景**:
阅读技术文档、设计文档、知识库文档，需要清晰排版与结构化导航。

**操作示例**:
```
用户目标: 阅读一份含目录、表格与本地截图的文档
操作步骤:
1. 在文件列表点击该文档
2. 在侧边栏「目录」视图中点击某个章节标题
结果: 页面平滑滚动到该章节，目录中该条目高亮；
      继续向下滚动，高亮随当前所在章节自动移动
```

**源码位置**: `LightMDKit/public/app.js:1098-1151`（渲染并展示文件）、`1140-1149`（Mermaid）、`1160-1199`（相对路径图片解析）、`933-983`（TOC 生成与跳转）、`2088-2104`（滚动高亮监听）；渲染增强规则见 `LightMDKit/public/md-render.js:190-197`

#### 4. 编辑文档并保存（传统模式）

**用户可以做什么**:
- 点击「编辑」进入编辑态，直接在 Markdown 原文上修改
- 点击「浏览」退出编辑态：**先写回原文件**，再重新渲染预览
- 编辑态下每 3 秒自动保存一次，不必手动触发

**使用场景**:
阅读时发现错别字、过时信息或需要补充说明，希望就地修改并立即看到渲染结果。

**操作示例**:
```
用户目标: 修正文档中的一处描述
操作步骤:
1. 打开目标文档并阅读到相应位置
2. 点击「编辑」——光标自动定位到当前视口最上方章节对应的源码位置
3. 修改内容（期间每 3 秒自动保存一次）
4. 点击「浏览」
结果: 内容写回磁盘上的原文件，页面重新渲染预览，滚动位置回到切换前的章节
异常: 文件来源不可写（例如拖入的单个文件）时提示「当前文件来源不支持写回保存」，
      但仍会退出编辑态、不会卡住
```

**源码位置**: `LightMDKit/public/app.js:1705-1774`（编辑 / 浏览切换）、`1531-1552`（写回保存）、`1554-1572`（3 秒自动保存）、`1715-1734`（位置同步）

#### 5. 现代模式（Typora 式即时渲染）

**用户可以做什么**:
- 点击「现代模式」切换为单栏常驻编辑：没有「编辑 / 浏览」按钮，编辑区就是成品
- 语法标记（`#`、`**`、链接地址等）默认隐藏，光标移到某一行时该行还原为源码，方便修改标记
- 编辑时目录（TOC）与滚动/光标高亮实时跟随；编辑内容每 3 秒自动保存
- 再次点击「传统模式」切回编辑 / 浏览分离的界面，选择被浏览器本地记住，下次打开仍是上次的模式

**使用场景**:
用户需要「边写边看」的连续写作体验，而不是改一次切一次。

**操作示例**:
```
用户目标: 用 Typora 式体验连续写作
操作步骤:
1. 点击工具栏「现代模式」
2. 直接在编辑区输入内容（标题、粗斜体、删除线、列表都即时呈现成品样式）
结果: 光标所在行显示源码，其余内容显示为成品样式；每 3 秒自动落盘；
      目录面板跟随编辑内容实时更新
备注: 图片与 Mermaid 图表在这一版仍以源码形式显示（未做图内渲染）
```

**源码位置**: `LightMDKit/public/app.js:1660-1703`（模式切换与持久化）、`1614-1657`（三种界面形态的显隐）、`413-469`（编辑时目录与删除线实时刷新）；观感规则见 `LightMDKit/public/style.css:700-1002`

#### 6. 在文档之间导航

**用户可以做什么**:
- 点击文档中的相对路径链接，在当前页面直接打开目标 Markdown 文件（支持 `./a.md`、`sub/a.md`、`sub\a.md` 等写法）
- 点击「← 返回」退回上一个打开的文件

**使用场景**:
文档之间存在交叉引用（如业务文档引用《业务流程详解》），需要在关联文档间快速往返。

**操作示例**:
```
用户目标: 从核心业务领域跳到业务流程详解再回来
操作步骤:
1. 在文档中点击 [查看](./业务流程详解.md) 链接
结果: 页面切换到「业务流程详解.md」，「← 返回」按钮变为可用
2. 阅读完毕后点击「← 返回」
结果: 页面退回「核心业务领域.md」
```

**源码位置**: `LightMDKit/public/app.js:1505-1540`（链接拦截与打开）、`1520-1529`（返回）、`1256-1275`（打开文件）

#### 7. 拖放打开文件 / 文件夹（新标签页）

**用户可以做什么**:
- 把一个或多个 `.md` / `.markdown` 文件拖入页面，在新标签页打开
- 把整个文件夹拖入页面，在新标签页加载该目录
- 拖入时页面显示投放提示层

**使用场景**:
用户正在浏览另一个目录，临时想对照某个文件 / 目录，不想打断当前页面。

**操作示例**:
```
用户目标: 临时打开资源管理器里的一个 Markdown 文件
操作步骤:
1. 从资源管理器拖动文件到 LightMDKit 页面（出现「松开鼠标，在新标签页打开…」提示）
2. 松开鼠标
结果: 新标签页打开该文件；若该文件位于当前已加载的文件夹内，新标签页的
      文件列表会自动定位到它所在目录并高亮该文件
异常: 拖入不支持的类型时提示「仅支持拖入 .md / .markdown 文件或文件夹」；
      浏览器拦截弹窗时，状态栏给出「点击打开」链接兜底
```

**源码位置**: `LightMDKit/public/app.js:1982-2022`（处理投放）、`2034-2082`（新标签页恢复）、`1863-1958`（句柄经 IndexedDB 传递、弹出被拦截的兜底）

### 管理能力

#### 8. 刷新与重新扫描

**用户可以做什么**:
- 点击「刷新」重新扫描当前文件夹（含子目录），感知新增 / 删除的文件，并重新读取当前文件内容
- 若当前文件已被外部删除，页面给出「当前文件已被移除」提示
- 未通过「加载文件夹」打开、而是拖入的单个文件，刷新时只重新读取该文件本身

**使用场景**:
文件被外部编辑器（VS Code、记事本等）或 Git 操作改动后，需要同步最新内容。

**源码位置**: `LightMDKit/public/app.js:1293-1354`

#### 9. 侧边栏与界面管理

**用户可以做什么**:
- 切换侧边栏面板：「文件列表」/「目录」（选择被浏览器本地记住）
- 点击箭头折叠 / 展开侧边栏（折叠后仅保留 40px 的展开条）
- 拖动侧边栏右边缘调整宽度（约 200px ~ 500px）
- 点击「新tab页」打开一个新标签页继续使用

**使用场景**:
屏幕空间有限或需要双屏对照；或按阅读习惯调整导航区宽度。

**源码位置**: `LightMDKit/public/app.js:1797-1818`（视图切换）、`1784-1795`（折叠）、`1848-1883`（拖拽调宽）、`1498-1503`（新标签页）；折叠宽度见 `LightMDKit/public/style.css:139-143`

### 查询能力

- **文件定位**：通过侧边栏文件列表 + 过滤框按文件名 / 相对路径实时筛选（`LightMDKit/public/app.js:1038-1044`）。
- **章节定位**：通过目录（TOC）跳转到文档内任意 1~6 级标题；浏览态下由滚动位置驱动高亮（`LightMDKit/public/app.js:937-988`、`2111-2126`）。
- 本服务**不提供**全文检索、跨文件搜索、统计报表等数据查询能力。

## 用户角色和权限

### 角色说明

| 角色名称 | 角色描述 | 可以做什么 | 不能做什么 |
|---------|---------|-----------|-----------|
| 本地使用者（唯一角色） | 在同一台机器上启动服务并用浏览器访问的用户；服务不区分账号 | 加载任意有权限的本地文件夹；浏览、过滤、跳转全部 Markdown；编辑并写回原文件；切换界面模式与侧边栏布局；拖放打开文件 | 不能登录 / 注册（无账号体系）；不能跨设备或跨用户访问；不能访问当前所选文件夹之外的文件；对选择为只读来源的文件无法写回保存 |
| 外部脚本 / 第三方程序 | 不通过浏览器界面，直接调用服务端 HTTP 接口的程序 | 调用 `/api/load`、`/api/file`、`/api/refresh` 读取目录与文件；在 Windows 上调用 `/api/select-folder` 弹系统目录框 | 无鉴权约束，但仅能访问服务进程有权限的文件；不能编辑 / 写回文件（接口均为只读语义） |

### 权限边界

- **无鉴权体系**：服务未实现任何登录、Token、角色或权限校验，任何能访问 `http://localhost:3456` 的进程都可以使用全部功能（`LightMDKit/server.js:10-14`）。
- **权限来源是操作系统的文件权限 + 浏览器授权**：读写的实际边界由「用户在选择文件夹时授予的读写授权（`showDirectoryPicker({ mode: 'readwrite' })`）」和操作系统对当前用户的文件权限共同决定（`LightMDKit/public/app.js:1254`）。
- **写入范围**：只有通过「加载文件夹」取得的目录内文件带有可写句柄；拖入的单个文件通常不具备写回能力（提示「当前文件来源不支持写回保存」）。
- **数据边界**：所有文件内容只在浏览器内存与本地磁盘之间流转，服务端不落库、不上传、不留副本。
- **监听地址未做限制**：服务以 `app.listen(3456)` 启动，未限定绑定地址（默认监听全部网卡），叠加「无鉴权」，因此在不受信任的网络中运行时，同一网络内的其他机器理论上也能访问该服务（`LightMDKit/server.js:276`）。

## 业务规则（用户需要知道的）

### 使用限制

- **文件类型**: 只识别 `.md` 和 `.markdown` 两种扩展名，其他文件不会出现在文件列表中（`LightMDKit/public/app.js:179-182`）。
- **扫描范围与上限**: 递归扫描子目录，最多 **6 层**深、最多 **3000** 个文件；超过上限时停止继续深入（已扫到的文件照常可用，不报错）（`LightMDKit/public/app.js:91-92`、`230-254`）。
- **自动跳过的目录**: `node_modules`、`.git`、`.svn`、`.hg`、`.idea`、`.vscode`、`dist`、`build` 会被跳过，其中的 Markdown 不会出现在列表里（`LightMDKit/public/app.js:94-96`）。
- **浏览器要求**: 文件夹选择依赖浏览器原生 File System Access API，需要 Chrome / Edge 等 Chromium 内核浏览器；不支持时给出明确提示（`LightMDKit/public/app.js:1248-1251`）。
- **服务端口固定**: 服务固定监听 `3456`，不可通过配置修改（`LightMDKit/server.js:11`）。
- **单文件夹**: 一个页面同时只能加载一个文件夹，切换文件夹即替换当前列表（`LightMDKit/public/app.js:1216-1244`）。
- **侧边栏宽度**: 拖拽调宽的有效范围约 200px ~ 500px，超出范围的拖动不生效；折叠后宽度固定 40px（`LightMDKit/public/app.js:1860-1869`、`LightMDKit/public/style.css:139-143`）。
- **「新tab页」按钮**: 只打开同一个页面地址，**不会带上当前已加载的文件夹**，新标签页里需要重新点「加载文件夹...」。
- **拖入单个文件的定位限制**: 受浏览器安全限制，拖入的单个文件拿不到其所在目录，除非该文件正好在当前已加载的文件夹内（按文件句柄比对判断），否则新标签页只能打开这一个文件，顶部目录名处会提示无法定位所在目录（`LightMDKit/public/app.js:1947-1957`、`2060-2076`）。
- **现代模式的展示边界**: 现代模式是「带成品样式的源码视图」——标题、粗斜体、删除线、链接文字按成品样式呈现，但**图片与 Mermaid 图表仍以源码形式显示**；同时该模式下不执行图片解析与图表渲染（`LightMDKit/public/app.js:1123-1125`、`1153-1162`、`LightMDKit/public/style.css:985-990`）。
- **现代模式的目录解析方式**: 目录与跳转位置按文档原文「行首 `#`」解析，因此代码块中以 `#` 开头的行也会被当成标题列进目录；传统模式的目录按渲染结果解析，没有这个问题（`LightMDKit/public/app.js:374-395`、`285-300`）。
- **离线可用性**: 页面样式与前端库（github-markdown-css、CodeMirror、mermaid、marked）随服务一起发布在 `public/vendor/` 并打进 exe 快照，**完全不需要访问外网**（`public/index.html:20-28`、`136-144`）。2026-10-08 起如此；此前这些库来自 jsDelivr CDN，离线机器上打开文件/切模式会报 `Cannot read properties of undefined (reading 'parse')`。
- **状态提示自动消失**: 界面右上角的状态提示约 3 秒后自动清除，属正常现象（`LightMDKit/public/app.js:167-177`）。

### 业务约束

- **保存前必有写权限**: 只有通过文件夹授权获得可写句柄的文件才能保存；写回失败会明确提示「当前文件来源不支持写回保存」或「保存失败: …」，不会静默丢弃（`LightMDKit/public/app.js:1553-1574`）。
- **自动保存节奏为 3 秒**: 编辑态下每 3 秒落盘一次；退出编辑态（点「浏览」）或切换界面模式时会额外保存一次（`LightMDKit/public/app.js:98-99`、`1554-1572`、`1690-1698`、`1646-1654`）。
- **切换文件会退出编辑态**: 在传统模式下编辑时点击其它文件，会先退出编辑态并加载新文件；当前实现**没有**在切换前强制保存，因此最近一次自动保存之后（最多 3 秒内）的新改动不会写盘（`LightMDKit/public/app.js:1269-1288`）。同理，编辑态下点「刷新」会以磁盘内容覆盖编辑器中的未落盘改动（`LightMDKit/public/app.js:1293-1354`）。
- **同名文件靠相对路径区分**: 子目录中允许存在同名文件，文件列表与管理均以「相对路径」为准（`LightMDKit/public/app.js:1023-1091`、`188-196`）。
- **链接匹配规则宽松**: `./a.md`、`a.md`、`sub\a.md` 等写法都会先相对「当前文件所在目录」解析，再退回「相对根目录」解析；只有 `http(s)`、`mailto`、纯锚点 `#`、`//` 开头的链接不被拦截（`LightMDKit/public/app.js:186-188`、`1352-1518`）。
- **图片解析规则**: 文档中的相对路径图片按当前文件夹逐级解析（支持子目录），同一张图片只读取一次并缓存；截图被替换后需要点击「刷新」重新扫描，加载新文件夹时缓存会被释放（`LightMDKit/public/app.js:1164-1212`）。
- **删除线只认双波浪线**: `~~删除~~` 才会渲染成删除线；中文里常见的范围写法（如 `1~100`、`2~5`）不会被误判（`LightMDKit/public/md-render.js:158-188`）。
- **表格与缩进增强**: 支持单元格内换行的表格（用 `<br>` 合并续行）、保留原文中的缩进（以不换行空格呈现）、单行换行按换行渲染（`LightMDKit/public/md-render.js:10-57`、`72-132`、`190-197`）。
- **拖放记录 24 小时过期**: 拖放时临时存放的句柄数据保存在浏览器 IndexedDB 中，超过 24 小时的记录会被清理；过期后再打开该标签页会提示「拖放数据不存在或已过期」（`LightMDKit/public/app.js:1885-1887`、`1899-1919`）。

### 状态流转（用户视角）

- **界面模式**: 传统模式（浏览）→ 点击「编辑」→ 传统模式（编辑）→ 点击「浏览」→ 传统模式（浏览，内容已保存）；传统模式 ↔ 点击「现代模式 / 传统模式」↔ 现代模式（始终为编辑态，持续自动保存）。
- **文档状态**: 未加载（空状态提示）→ 已加载（渲染预览）→ 编辑中（原文 + 每 3 秒自动保存）→ 已保存（重新渲染）。
- **浏览历史**: 空栈（「← 返回」不可用）→ 点击文件列表 / 文档内链接压栈（按钮可用）→ 点击「← 返回」弹栈。
- **文件存在性**: 存在 → 被外部删除 → 点击「刷新」后提示「当前文件已被移除」。

## 业务边界

### 本服务提供的能力

- 加载本地文件夹（含子目录）并列出其中所有 Markdown 文件
- 侧边栏文件列表：按目录分组、实时过滤、当前文件高亮，与目录（TOC）视图一键切换
- GitHub 风格渲染阅读：表格、代码块、Mermaid 图表、相对路径图片
- 目录（TOC）生成、章节跳转与滚动 / 光标高亮
- 传统模式：编辑 / 浏览分离，手动保存 + 3 秒自动保存
- 现代模式：Typora 式即时渲染的单栏编辑体验（无编辑 / 浏览按钮）
- 文档内相对路径链接跳转与「返回」历史
- 刷新重新扫描，感知新增 / 删除的文件
- 拖放打开 `.md` 文件 / 文件夹（新标签页，尽量定位到所在目录）
- 界面偏好本地记忆（界面模式、侧边栏视图）与侧边栏折叠 / 拖拽调宽
- 4 个只读的服务端 HTTP 接口，供外部脚本 / 第三方程序按目录或路径取文件与渲染结果

### 不提供的能力

- **不提供账号与权限体系**: 无登录、无注册、无角色、无鉴权（任何能访问 `localhost:3456` 的程序都能用全部功能）。
- **不提供服务端存储与上传**: 文件不经过服务端读写、不上传、不落库，服务端不保存任何文档副本。
- **不提供云端 / 跨设备能力**: 无同步、无协作、无分享链接。
- **不提供版本管理**: 无 Git 集成、无历史版本、无改动对比、无撤销栈（保存即覆盖原文件）。
- **不提供新建 / 删除 / 重命名文件**: 只能在已有文件上编辑内容（`feature-todo.md` 中「新增文件」仍为待办）。
- **不提供全文搜索**: 只有文件名 / 路径过滤与章节跳转，没有跨文件内容检索、替换。
- **不提供导出**: 不导出 PDF / HTML / 图片，也没有打印排版。
- **不提供多文件夹同时加载**、不提供只读预览与编辑的分栏对照。

### 与其他服务的协同

- **本地文件系统**: 唯一的真实数据源与存储介质；文件的读取与写回都通过浏览器 File System Access API 直达磁盘。
- **操作系统**: 文件夹选择对话框由浏览器提供；Windows 上服务端另有一条基于 PowerShell 的系统对话框接口（`LightMDKit/server.js:19-94`），但前端默认不使用。
- **服务端 HTTP 接口**: 前端不调用任何 `/api/*` 接口（`LightMDKit/public/app.js` 中不存在 `fetch` / `XMLHttpRequest` 调用），这 4 个接口是提供给外部脚本 / 第三方程序的可选通道，调用方式见 [外部接入指南](../外部接入指南.md)。
- **前端三方库（本地，非外部依赖）**: 前端样式与库文件（github-markdown-css、CodeMirror、mermaid、marked）来自 `public/vendor/`，随包分发，**没有运行期外部依赖**，断网环境下页面功能完整。2026-10-08 起由 CDN 改为本地化。
